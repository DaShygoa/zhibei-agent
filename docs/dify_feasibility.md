# 迁移到 Dify 的可行性评估（2026-11-23 调研）

资料来源：docs.dify.ai（Agent 应用、Agent 节点、知识库元数据、知识检索节点、工具、代码节点、变量赋值）、dify.ai/pricing、dify.ai/education。

## 1. Dify 相关能力速查

| 能力 | 文档结论 | 对本项目的意义 |
|---|---|---|
| Agent 应用（经典） | Function Calling / ReAct 策略自动选择；可设最大迭代次数；**知识库由 Agent 自行决定是否检索** | 满足"自主决策 + 工具调用" |
| 新版 Agent（beta） | 自带沙箱、可执行命令；Docker 部署默认开启；文档未说明云版可用性 | 不稳定，不采用 |
| Agent 记忆 | 每个会话最多 500 条消息或 **2000 tokens**，超出丢弃最早消息；新会话从零开始 | 多轮"抽题→作答"需要设计紧凑的状态传递 |
| 知识库元数据 | **文档级**（不是分段级）；类型 string/number/time；可通过 API 批量设置 | 按考点/题型过滤 → 需按"考点×题型"拆分文档 |
| 元数据过滤 | 知识检索节点支持手动/自动；手动模式条件值**可引用工作流变量**；AND/OR；大小写敏感；文档未说明 Agent 应用是否支持 | 用"工作流发布为工具"实现精确抽题 |
| 工作流发布为工具 | 以用户输入节点开头的 Workflow 可发布成工具，Agent 应用可调用；Chatflow 不行 | 抽题工具、判分工具都能在 Dify 内实现，**无需外部服务** |
| 自定义工具 | 导入 OpenAPI/Swagger；MCP（仅 HTTP 传输） | 可选：接现有 Python 工具服务 |
| 代码节点 | Python/JS 沙箱，含 json/re/base64 等标准库；array[object] 默认最多 30 项；对象嵌套 5 层；可重试与异常分支 | 判分逻辑可直接移植 |
| 会话变量 | 仅 Chatflow；仅在**同一会话内**持久 | 跨会话错题本需外部存储 |
| 可观测性 | 内置 Langfuse / LangSmith / Opik / Phoenix 等集成 | 满足 Trace 要求 |
| 发布 | Web App 公开链接、嵌入网页、Service API、MCP Server；DSL 导出/导入 | **分发最方便** |

## 2. 云版额度（cloud.dify.ai）

| 项目 | Sandbox（免费） | Professional / 教育版 |
|---|---|---|
| 应用数 | 5 | 50 |
| 知识库文档数 | **50** | 500 |
| 向量存储 | 50 MB | 5 GB |
| 知识检索频率 | **10 次/分钟** | 100 次/分钟 |
| 赠送消息额度 | 200（不重置），用完可接自己的模型 Key | 同左（教育版不含额度） |

- Dify for Education：用**学校邮箱**认证，免 Professional 年费；是否认可国内高校邮箱以 Dify 审核为准。
- 题库按"考点×题型"拆分共 **57 个文档**，超过 Sandbox 的 50 个上限：要么合并小组合，要么申请教育版，要么本地 Docker 自部署（无限制，但公网分发要做内网穿透）。

## 3. 推荐的 Dify 方案

```text
Agent 应用（Function Calling，最大迭代 8）
 ├─ 工具① draw_quiz（Workflow 工具）
 │    输入 topic / qtype / keyword / n
 │    → 知识检索节点（手动元数据过滤：topic=变量, qtype=变量）
 │    → 代码节点：去掉答案，生成"测验码"（答案经编码，Agent 原样转交即可）
 ├─ 工具② grade_answers（Workflow 工具）
 │    输入 测验码 + 用户答案 → 代码节点解码并确定性判分，给出漏选/错选诊断
 ├─ 知识库（讲解时由 Agent 自主检索）
 └─ 监控：Langfuse
```

- "测验码"让判分不依赖 2000 tokens 的记忆窗口，也不需要外部数据库。
- 知识库数据直接复用 Python 解析结果：一题一段，自定义分隔符，文档级元数据为 topic / qtype / bank。
- 评测：调用 Dify Service API 对话，读取消息里的 agent_thoughts，检查工具调用，复用 13 条用例。

## 4. 与评分标准的匹配度

| 评分项（分值） | LangGraph 版 | Dify 版 | 说明 |
|---|---|---|---|
| Agent 能力真实性（25） | 高 | 高 | 两者都是模型自主调用工具 |
| 架构设计合理性（15） | 高 | 中高 | Dify 的循环与记忆由平台托管，可定制项少 |
| 工具开发质量（15） | 高 | 中高 | 工作流工具 + 代码节点，错误处理靠异常分支 |
| Prompt 工程（10） | 同 | 同 | Prompt 可直接复用 |
| 评测与可观测性（15） | 高 | 高 | Langfuse 一键接入；API 可自动评测 |
| 工程规范与部署（10） | 高 | 中 | Dify 版靠 DSL + 导入脚本复现，环境隔离较弱 |
| 报告深度（10） | — | — | 两版对比本身就是加分点 |
| **分发便利性**（非评分项） | 中（需自行部署） | **高**（公开链接） | |

**主要缺口**：跨会话长期记忆（错题本、薄弱分）。可选补法：在工作流里用 HTTP 请求节点读写外部 KV（如 Upstash Redis REST，免费额度），不需要自己托管服务。
