# 从 Dify 工作流到 LangGraph Agent：改造对比

原版为 Dify Chatflow「华为ICT大赛昇腾AI赛道备赛助手」（DSL 格式 0.3.1）。原导出含本机绑定信息，不随仓库上传。

## 原版流程

开始 → 循环(1 次) → 问题分类器（题目训练 / 知识点讲解）
- 题目训练：LLM 随机抽 3~6 个关键词 → 知识库检索 → LLM 生成 7 道题 + 答案 + 解析 → 关键词写入 `study_history`
- 知识点讲解：LLM 提取关键词 → 知识库检索 → LLM 讲解

## 对比

| 维度 | Dify 原版（工作流） | 智备（LangGraph Agent） |
|---|---|---|
| 控制方式 | 固定 DAG，分类器二选一分支 | ReAct 循环，LLM 自主决定调用哪些工具、调用几次 |
| 题目来源 | LLM 现场生成（可能编错题/错答案） | 从 1710 道真题抽取，LLM 不能编题 |
| 判分 | 无，题目和答案一次性全部给出 | `grade_answers` 确定性判分，多选给出漏选/错选诊断 |
| 记忆 | `study_history` 只存关键词；LLM 记忆窗口关闭；`point` 变量未使用 | 短期：对话 checkpointer；长期：作答记录 → 错题本、考点正确率、薄弱分 |
| 个性化 | 只避免关键词重复 | 按薄弱考点出题、错题重练、画像诊断与练习计划 |
| 题库利用 | 作为检索参考上下文 | 结构化入库（题型/考点/答案/解析），可按条件筛选 |
| 错误处理 | 无 | 工具返回 error+hint 让 Agent 自我修正；步数上限防死循环 |
| 可观测性 | Dify 自带日志 | 工具事件 + 13 条自动化评测；Langfuse 支持可选，未接通 |
| Prompt 问题 | 判断题"2 选项"与"4 选项"要求矛盾；循环与"结束备赛"判断无实际作用；大纲仍写"第九届" | 规则化 Prompt + Few-shot 决策示例，禁止事项明确 |
| 部署 | 依赖 Dify 实例，知识库 ID 无法随导出文件迁移 | Docker 可运行自编样例；完整题库需自行导入 |

## 结论

Dify 适合快速搭原型；但"出题—作答—判分—记错—针对性再练"是一个需要**根据中间结果动态决定下一步**的任务，固定工作流很难表达，正是 Agent 的用武之地。
